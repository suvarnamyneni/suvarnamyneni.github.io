Before

Hours were recorded, then collated by hand.

A working day has productive and non-productive hours. Timelog is a structured way to register both. It removes the manual effort of collating data, and gives a team manager one-click access to the team's complete non-Sherlock time data.

The earlier shape of the work, as the case study lists it: manual registration for access, associates recording non-productive time, and managers downloading a full dump to filter in Excel.

What changed

One password, default access, edits that need a manager.

  • Revamped UI More intuitive and responsive, aimed at navigation and usability issues in the earlier version.
  • Download center Managers filter and export to an Excel file.
  • Password Authentication uses Conclave login credentials, so internal tools share a single password.
  • Access Manual registration is replaced with default access for all Conclave users.
  • Ownership Associates can edit their own data. A manager still has to approve the change.

Login

Amazon alias and password.

People log in with their Amazon alias and password.

Associate view

Start the clock. Stop ends it.

History lets associates view and edit timelog data. An edit has to be approved by the manager. If the manager rejects or updates it, the associate sees that change listed here.

Manager view

Download a person, or the whole team.

Cache is where a manager downloads timelog reports, for one person or the team. History is where they view and edit associates' logs, and where associate edits wait for a response. Rejecting an entry can include a reason.
