Problem

Information is everywhere. Starting still isn't.

Real estate investment has become a popular route to financial stability, and it is a complex process that needs guidance. Blogs and agencies publish a lot of information. First-time buyers can still struggle to begin without professional guidance, and spend time viewing properties outside their budget.

Perfect Properties is a responsive web app with information on properties of interest, and help getting started on buying a home.

Discover · 5 W's

New buyers, at home or on the go.

  • Who Primarily new, small-scale property buyers investing for additional income or financial security.
  • What A responsive web app with a database of residential properties and land, and fuller information on each listing.
  • When While searching, and while deciding where to invest.
  • Where At home or on the go, on any device, once they are logged in.
  • Why Unseasoned buyers need reliable, uncomplicated information. They get a feel for a place, and its neighborhood, before spending time on site.

Define

One persona, from the brief.

The project started from a brief with specific requirements. From that brief I built a persona for the target group: needs, objectives and experiences. The flow later follows the screens Rashida moves through to finish her tasks. Two moodboards were made for her, and Moodboard 1 was the one that matched her.

User stories

Search, save, learn, then book a viewing.

  1. 01

    Search and filter

    So I can find good matches based on my needs.

  2. 02

    Save or mark

    So I can revisit properties I am interested in.

  3. 03

    Read and see more

    As much written and visual information as possible, so I can decide.

  4. 04

    Contact the right people

    If I want to view a property, so I can schedule it.

Ideate and design

Flow, then wireframes that can reflow.

The user flow is the sequence of screens Rashida needs. Low-fidelity wireframes set layout and content. Mid-fidelity wireframes moved toward flexible content blocks so the same screens hold up across devices.

Moodboard and style

Moodboard 1 matched Rashida.

Two moodboards set a visual direction. Moodboard 1 was selected because it was closer to the intended character of the target user. The style guide covers color, typography, logo, buttons, iconography, UI elements and imagery.

Iterate

Mobile first, then the wider breakpoints.

After the mobile-first approach, progressive enhancement adjusted the design for larger breakpoints. The hard part was larger screens: more room for content, and a real risk of overloading it. The work was choosing what each breakpoint actually needs, and keeping whitespace. The case study includes a high-fidelity prototype and polished mockups.

What I learned

The moodboard was the direction, not a decoration.

  1. 01

    Moodboard as a guide

    It set the direction of the design, not only the look.

  2. 02

    Visual hierarchy

    A consistent hierarchy is how the interface tells a clear story.

  3. 03

    UI elements

    Integrating them raised the quality of the deliverable and made the product easier to navigate.
